## 1. 引言

### 1.1 编写目的

本文档说明如何构建、运行和验证 LightDemo 项目。使用者可以按照本文档在 Ubuntu 22.04 虚拟机中完成构建、QEMU 运行、串口输入、故障注入和状态查询。

### 1.2 项目简介

LightDemo 是一个 seL4 + Microkit 汽车车灯控制演示系统。系统通过 UART 接收命令，通过 scheduler 进行规则裁决，通过 lightctl 执行控制，通过 gpio 输出结果，并通过 faultmg 管理故障模式和恢复过程。

## 2. 系统用途

### 2.1 功能

系统支持：

- 近光灯、远光灯、转向灯、示廓灯、制动灯控制。
- 车辆状态参与控制裁决。
- 故障注入。
- 故障升级。
- 安全降级输出。
- clear 与逐级恢复。
- 统一状态快照查询。

### 2.2 性能与稳定性

本项目运行在 QEMU 模拟环境中，主要用于工程验证和教学展示。系统通过自动化脚本验证启动、命令传播、故障注入和串口状态查询流程。

## 3. 运行环境

### 3.1 硬件环境

推荐：

- CPU：普通 x86_64 PC 或虚拟机即可。
- 内存：建议 4GB 以上。
- 磁盘：建议 2GB 以上可用空间。

### 3.2 软件环境

推荐环境：

- Ubuntu 22.04
- Microkit SDK 2.0.1
- `aarch64-linux-gnu-gcc`
- `qemu-system-aarch64`
- `make`
- `bash`

检查命令：

```bash
command -v make
command -v qemu-system-aarch64
command -v aarch64-linux-gnu-gcc
```

## 5. 构建项目

```bash

build/loader.img

```

如果 Microkit SDK 不在默认位置，可以指定：

```bash

```

```bash

```

## 6. 运行项目

### 6.1 启动 QEMU

```bash
make run
```

系统启动后会看到各 protection domain 的初始化日志，例如：

```text
CMD_INIT module=commandin status=ready
SCHED_INIT module=scheduler status=ready
LIGHTCTL_INIT module=lightctl status=ready
GPIO_INIT module=gpio status=ready
FAULT_INIT module=faultmg status=ready
```

### 6.2 退出 QEMU

在终端中通常可以使用：

```text
Ctrl + A, X
```

或直接终止运行进程。

## 7. 串口命令说明

### 7.1 灯光控制命令

| 功能 | 打开 | 关闭 |
| --- | --- | --- |
| 近光灯 | `L` | `l` |
| 远光灯 | `H` | `h` |
| 左转向灯 | `Z` | `z` |
| 右转向灯 | `Y` | `y` |
| 示廓灯 | `P` | `p` |
| 制动灯 | `B` | `b` |

示例：

```text
L
H
B
```

对应日志中可以观察：

```text
CMD_MSG type=light_cmd
SCHED_TARGET
LIGHTCTL_TARGET_SUMMARY
GPIO_OUTPUT_SUMMARY
```

### 7.2 故障管理命令

| 输入 | 含义 |
| --- | --- |
| `!` | 注入 `LIGHT_ERR_MODE_CONFLICT` |
| `#` | 注入 `LIGHT_ERR_HW_STATE_ERR` |
| `C` | clear active faults 或触发 elapsed-time recovery 演示路径 |
| `?` | 输出统一状态快照 |

### 7.3 状态快照

输入：

```text
?
```

输出示例：

```text
STATUS_SNAPSHOT fault=SAFE_MODE lifecycle=ACTIVE recovery_ticks=0/2 recovery_elapsed_ms=0/2000 active_faults=0x08 ... layout=4 contract=OK
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `fault` | 当前 fault mode |
| `lifecycle` | 当前生命周期 |
| `recovery_ticks` | 兼容展示用恢复步数 |
| `recovery_elapsed_ms` | 已累计恢复时间 / 恢复窗口，final v2.0 的主要恢复依据 |
| `active_faults` | active fault 位图 |
| `speed` | 车辆速度 |
| `target` | 当前目标输出 |
| `allow` | 输出 bitset |
| `last_fault` | 最近故障码 |
| `total_faults` | 故障计数 |

### 7.4 手动演示时怎么看结果

`make run` 现场手动输入字符时，建议按“输入命令、看三类关键日志、再查询状态”的顺序展示：

```text
L
?
#
#
?
C
?
```

观察重点：

| 日志 token | 说明 |
| --- | --- |
| `CMD_MSG` | `commandin` 已收到并解析串口命令。 |
| `SCHED_TARGET` | `scheduler` 已结合车辆状态和 fault mode 得出目标灯光。 |
| `LIGHTCTL_TARGET_SUMMARY` | `lightctl` 已生成执行计划。 |
| `GPIO_OUTPUT_SUMMARY` | 最终灯光输出摘要，答辩时主要看这里确认灯是否亮。 |
| `FAULTMG_EVENT` / `FAULTMG_HISTORY` | 故障被 faultmg 记录和升级。 |
| `STATUS_SNAPSHOT` | 当前 fault、车辆状态、目标输出、layout 和 contract 汇总。 |

如果现场日志较多，优先找 `GPIO_OUTPUT_SUMMARY` 和 `STATUS_SNAPSHOT`。前者说明“灯实际输出是什么”，后者说明“系统当前状态为什么是这样”。

## 9. 常见问题

### 9.1 找不到 make

现象：

```text
make: command not found
```

解决：

```bash
sudo apt install make
```

### 9.2 找不到交叉编译器

现象：

```text
Could not find an AArch64 cross-compiler
```

解决：

```bash
sudo apt install gcc-aarch64-linux-gnu
```

### 9.3 找不到 QEMU

现象：

```text
qemu-system-aarch64: command not found
```

解决：

```bash
sudo apt install qemu-system-arm
```

### 9.4 SDK 路径不一致

默认 SDK 路径：

```text
../microkit-sdk-2.0.1
```

如果 SDK 不在该位置，使用：

```bash
make build MICROKIT_SDK=/path/to/microkit-sdk-2.0.1
```

### 9.5 QEMU 测试脚本等待日志超时

可能原因：

- 没有重新构建镜像。
- 脚本断言和日志格式不一致。
- QEMU 启动较慢。
- 串口输入被抢跑。

建议：

```bash
make build
make qemu-test
```

如果仍失败，查看脚本输出的 `qemu.log tail`。
