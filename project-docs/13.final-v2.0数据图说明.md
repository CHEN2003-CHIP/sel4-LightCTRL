# LightDemo Final v2.0 数据图说明

## 1. 展示目的

传统后端项目可以用压测吞吐量、延迟曲线说明系统表现，大模型项目可以用 loss 曲线说明训练过程。LightDemo 是嵌入式安全控制类项目，因此最终版采用以下数据图说明工程结果：

- 验证覆盖结果：证明最终版本不是只跑了单个样例，而是 host、QEMU、证据 token 全部通过。
- 场景 sweep 数据：通过 46,080 行车辆状态/故障模式组合，证明 v2.0 策略不是几个手工样例。
- 故障升级曲线：证明 fault taxonomy 与 fault lifecycle 有确定的升级路径。
- 恢复窗口曲线：证明 v1.1 已从 observation tick 升级为 elapsed-time recovery window。
- 车辆模型增长图：证明 v2.0 在业务模型复杂度上有明确增量。

推荐展示入口：

```text
reports/final_v2_metrics.md
```

### 3.2 Extended Scenario Sweep

该图展示新增 host-side sweep 的输入维度：

```text
5 request profiles x 6 speed points x 2 ignition states x 2 brake states
x 4 gears x 3 ambient states x 2 hazard states x 4 drive modes x 4 fault modes
= 46,080 rows
```

答辩话术：这部分相当于传统后端项目里的压测数据集，区别是这里压测的不是吞吐量，而是车辆状态、故障模式和灯光输出策略的组合空间。

### 3.3 Fault Escalation + Recovery Window

| 故障 | 曲线含义 |
| --- | --- |
| `MODE_CONFLICT` | 多次模式冲突后进入 `DEGRADED` |
| `HW_STATE_ERR` | 硬件状态错误重复出现后进入 `SAFE_MODE` |
| Recovery window | 清除故障后按 2000 ms 窗口逐级恢复 |

答辩话术：故障处理不是简单报警，而是有等级、有恢复策略、有运行日志证据。

### 3.4 Vehicle Model Growth

该图展示 v2.0 的业务模型增量：

| 版本 | 字段数 | 字段 |
| --- | ---: | --- |
| v1.0 | 3 | speed, ignition, brake |
| v2.0 | 7 | speed, ignition, brake, gear, ambient, hazard, drive mode |

答辩话术：v2.0 主线选择复杂车辆状态模型，扩展了夜间行驶、倒车/驻车、危险警示、急刹、故障降级等场景的策略输入。

## 4. 结论

这些图不是额外美化，而是把 final-v2.0 的测试证据、故障行为和业务模型增量可视化。答辩时建议先展示 `reports/final_v2_showcase.md`，随后切到 `reports/final_v2_metrics.md`，最后用 `manifest.txt` 和 QEMU log 证明图表数据可追溯。
