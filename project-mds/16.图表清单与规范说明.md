## 1. 编写目的

本文档用于统一说明 LightDemo 文档中的图表类型、位置和规范性处理方式，避免将工程流程图误称为 UML 图，也为后续 Markdown 转 Word 提供图表清单。

## 2. 图表规范原则

- 用例图必须包含参与者、系统边界和用例。
- 顺序图必须包含参与者、消息方向和关键返回或输出。
- 状态机图必须包含初始状态、状态、转移条件。
- 架构图、上下文图、测试闭环图属于工程图，不强行套用 UML 名称。
- 数据图应说明数据来源、图表含义和验证结论。

## 5. 图类型审查结论

当前文档不再缺少用例图；关键 UML 图包括用例图、顺序图和状态机图。其余图均按工程图处理，并在正文中明确说明，不冒充 UML 图。

Mermaid 对标准 UML 用例图没有原生 `usecaseDiagram` 语法，因此本文档使用 `flowchart` 表达 UML 用例图语义，并通过 `<<actor>>`、系统边界、椭圆用例和 `<<include>>` 关系满足课程文档表达要求。

## 6. 后续转换说明

当前环境未检测到 Mermaid CLI。若需要在 docx 中嵌入渲染后的图片，建议安装：

```bash
npm install -g @mermaid-js/mermaid-cli
```

安装后可将 Mermaid 代码块渲染为 PNG/SVG，再重新生成 docx。未安装前，docx 中保留 Mermaid 代码块和图题说明，便于人工复查和后续转换。
