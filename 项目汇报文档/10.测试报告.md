## 8. 关键测试用例说明

### 8.1 正常命令传播

测试命令：

```bash
make smoke
```

验证内容：

- `commandin` 接收 UART 输入。
- `scheduler` 更新 operator request。
- `lightctl` 生成 GPIO action。
- `gpio` 输出状态摘要。

关键日志：

```text
CMD_MSG type=light_cmd
SCHED_TARGET
LIGHTCTL_TARGET_SUMMARY
GPIO_OUTPUT_SUMMARY
```

### 8.2 故障注入与降级

测试命令：

```bash
make test-integration-fault
```

验证内容：

- mode conflict 多次注入后进入 `DEGRADED`。
- hardware-state error 多次注入后进入 `SAFE_MODE`。
- fault mode 更新会触发 scheduler 重新裁决。
- GPIO 输出进入保守状态。

关键日志：

```text
FAULTMG_MODE_TRANSITION
SCHED_TARGET mode=SAFE_MODE
LIGHTCTL_TARGET_SUMMARY mode=SAFE_MODE
GPIO_OUTPUT_SUMMARY
```

### 8.3 状态快照与恢复

测试命令：

```bash
make test-serial-e2e
```

验证内容：

- `?` 输出统一状态快照。
- `C` clear active faults。
- clear 后进入 `RECOVERING`。
- recovery tick 使故障等级逐级下降。
- `STATUS_SNAPSHOT` 显示 layout 和 contract 状态。

关键证据：

```text
STATUS_SNAPSHOT fault=SAFE_MODE lifecycle=ACTIVE ... layout=3 contract=OK
STATUS_SNAPSHOT fault=SAFE_MODE lifecycle=RECOVERING ... layout=3 contract=OK
STATUS_SNAPSHOT fault=DEGRADED lifecycle=RECOVERING ... layout=3 contract=OK
```

## 9. 缺陷与回归

### 9.1 已发现问题

在测试过程中，`report-v1` 和 `report-v2` 曾暴露 `commandin` 在处理 `?` 查询时发生 VMFault 的问题。

现象：

```text
faulting PD: commandin
VMFault: ip=0x0000000000000000
```

### 9.2 修复措施

修复方式：

- 降低 `commandin` 查询路径复杂度。
- 避免在 Microkit runtime 查询路径中使用复杂格式化调用。
- 直接逐字段读取 shared memory 并输出 `STATUS_SNAPSHOT`。
- 保留 `layout=` 和 `contract=` 工程证据字段。

### 9.3 回归结果

`report-v3` 中：

```text
test-serial-e2e PASS
```

且日志中存在：

```text
STATUS_SNAPSHOT ... layout=3 contract=OK
```

因此该缺陷已关闭。

## 11. 测试结论

根据 `test-results/report-v3/` 的测试证据，LightDemo 当前工程化版本通过最终验证：

- host-side 测试全部通过。
- QEMU 端到端测试全部通过。
- fault lifecycle、safe mode、recovery、contract snapshot 均有日志证据。
- 已发现的 `commandin` 查询 VMFault 已回归关闭。

因此，当前版本满足课程工程实践项目的测试验收要求。

## 12. 剩余风险

- 当前验证基于 QEMU，不覆盖真实硬件电气行为。
- 当前 fault taxonomy 较小，不等价于真实汽车系统完整故障集。
- recovery window 使用 observation tick，不是真实时间。
- 当前测试不构成功能安全认证证据。

这些风险已在安全说明和工程化总结中明确记录，不影响当前课程交付。
