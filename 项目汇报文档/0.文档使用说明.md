# LightDemo 项目汇报文档使用说明

本文件夹用于替代参考项目中的 Word 汇报材料，内容已按本项目实际实现重写。当前提供 Markdown 版本，便于继续维护，也便于复制到网页端 GPT、WPS 或 Word 中生成最终 `.docx`。

## 文档清单

| 文件 | 对应参考文档 | 用途 |
| --- | --- | --- |
| `1.软件需求分析.md` | `1.软件需求分析.doc` | 说明项目背景、需求、功能需求、非功能需求、可行性和验收条件。 |
| `2.概要设计.md` | `2.概要设计.doc` | 说明系统总体架构、保护域划分、通信关系、共享内存和测试设计。 |
| `3.详细设计说明书.md` | `3.详细设计说明书.docx` | 说明各模块内部设计、核心数据结构、fault lifecycle、算法和接口细节。 |
| `4.用户使用手册.md` | `4.用户使用手册.doc` | 面向使用者说明环境准备、构建、运行、串口操作和故障验证流程。 |

## 需要你最终替换的信息

文档封面中的以下字段使用了占位符，请在生成 Word 前按实际情况修改：

- 项目成员
- 班级 / 学号
- 指导老师
- 提交日期

## 推荐生成 Word 的方式

1. 将每个 Markdown 文件复制到网页端 GPT 或文档生成工具中。
2. 要求其“保持标题层级、表格、代码块、Mermaid 图，并生成适合工程实践提交的 Word 文档”。
3. 在 Word / WPS 中更新目录、页眉页脚和页码。

如果使用 Pandoc，也可以参考：

```bash
pandoc 1.软件需求分析.md -o 1.软件需求分析.docx
pandoc 2.概要设计.md -o 2.概要设计.docx
pandoc 3.详细设计说明书.md -o 3.详细设计说明书.docx
pandoc 4.用户使用手册.md -o 4.用户使用手册.docx
```
